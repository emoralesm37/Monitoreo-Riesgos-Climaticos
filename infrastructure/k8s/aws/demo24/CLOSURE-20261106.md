## Community Service independiente

Se creó **ClimateGuardCommunity**, propietario cg_community_app, dentro del PostgreSQL ya existente del despliegue nuevo. Es una base y un login separados; comparte proceso/PVC con Auth para evitar otro servidor/PVC. No se creó otra instancia, EBS o servicio AWS.

La migración EF se ejecutó mediante Job y pasó. Durante el cutover se bloquearon solo escrituras de comunidades mediante Gateway, se copió el registro inicial conservando ID y campos, se comparó la copia y se cambió la ruta de forma conjunta con la retirada de la barrera. Las escrituras están habilitadas. Se conservaron el origen SQL y el snapshot de comparación privado, sin imprimir datos privados.

Community obtiene sensorCount del endpoint autenticado de Sensor Service, no de su base. Sensor valida comunidades por API y conserva su propia proyección SQL para las claves foráneas existentes; no accede a PostgreSQL. Sus respuestas consultan el nombre autorizado desde Community. La prueba creó una comunidad nueva en PostgreSQL y un sensor asociado, verificó count=1 y conservó ambos tras reemplazar los Pods.

Legacy API sigue activo únicamente para compatibilidad de catálogos/reglas. No se borraron sus tablas ni se inició el despliegue Docker anterior. Nueve Deployments disponibles, frontend con dos réplicas; cuatro StatefulSets de bases y seis PVC Bound.

## Ingestión preparada, sin hardware

POST /api/sensors/{sensorId}/devices vincula dispositivo/sensor/UUID propietario y exige Administrador. POST /api/sensors/{sensorId}/readings/ingest exige JWT válido de Administrador u Operador, además de coincidencia con el propietario y sensor registrados. Se validan unidad, precisión, campos obligatorios y ventana temporal.

SQL conserva lectura, recibo único (deviceId, measurementId) y sobre de evaluación. Reintento idéntico: 200/mismo readingId; contenido diferente: 409. Cuatro solicitudes concurrentes produjeron una sola lectura y no duplicaron alertas. Se comprobó que una lectura antigua no sobrescribe el último valor. La deduplicación y la comunidad sobrevivieron al reemplazo de Pods. También pasó el flujo con Operador, no solo con Administrador.

[Contrato y configuración manual del puente Arduino Uno](ARDUINO-INGESTION.md). Sigue sin probarse cableado, calibración, reloj, firmware ni transporte USB/Wi-Fi físico. Debe persistirse el mismo sobre y timestamp durante reintentos; no incorporar credenciales OAuth ni claves de firma al firmware.

## GitHub: bloqueo externo pendiente y acción manual exacta

El propietario revocó el secreto compartido y configuró otro privadamente; confirmó que Google y otras claves permanecieron intactas. No se reprodujo ni se usó el secreto revocado. Google funciona según su prueba humana. GitHub llega a autorización, pero Chrome presenta el texto antiphishing/ingeniería social al retorno. No es un error de certificado TLS. No se confirmó una clasificación concreta de Safe Browsing ni un falso positivo.

Search Console, propiedad garher.lat verificada por DNS, indica «No se ha detectado ningún problema» según el propietario. El login y /oauth/callback sin parámetros abren normalmente en su perfil. TLS, Ingress, contenido estático y callbacks sin parámetros fueron verificados. Eso no demuestra que la URL real de retorno esté autorizada por Chrome. [Investigación previa](SAFE-BROWSING-20261106.md).

El siguiente paso seguro requiere al propietario:

1. Abrir el [formulario oficial de clasificación incorrecta](https://safebrowsing.google.com/safebrowsing/report_error/?hl=es).
2. Informar **https://climateguard.garher.lat/api/auth/callback/github**, sin query ni fragmento. No pegar la URL real de retorno, códigos, estado, cookies o tokens ni adjuntar capturas que los muestren.
3. Describir: «Soy propietario verificado de garher.lat. ClimateGuard es una aplicación universitaria. Chrome muestra Sitio peligroso únicamente al retornar de GitHub OAuth. La portada y el callback sin parámetros abren normalmente; Google OAuth funciona. Search Console no detecta problemas. Solicitamos revisar una posible clasificación incorrecta del callback legítimo».
4. Conservar el comprobante y esperar el resultado. Si Google señala contenido dañino, investigar/corregir ese hallazgo antes de pedir revisión. No se garantiza resolución inmediata ni se solicita atravesar el aviso. El retorno real GitHub sigue sin certificarse.

Esto sigue las [indicaciones oficiales de Chrome para propietarios](https://support.google.com/chrome/answer/99020?hl=es); no se envió un reporte en nombre del usuario ni se automatizó su cuenta.

## Incidencias reales y límites

- El primer Gateway publicado fuera del Dockerfile omitió el adaptador /health/ready y la comprobación respondió 401. Se restauró automáticamente la imagen anterior. Readiness se incorporó al código canónico y se añadieron pruebas; la versión corregida quedó disponible.
- Tras un rollout, Traefik/EndpointSlice tardó en reflejar endpoints. Se esperó la disponibilidad HTTP antes de continuar la migración; no se borró ni reimportó destructivamente la fuente.
- El primer bind de dispositivo dio 500 por atributos de validación en propiedades de records. Se corrigieron para asociarlos al constructor; el recorrido completo posterior pasó. La ejecución fallida y sus fixtures se conservaron.
- Una ejecución consecutiva de las suites alcanzó 429. Se conservó el rate limiter y la evidencia del intento; después de renovar su ventana, las 54 comprobaciones ampliadas pasaron sin errores HTTP. Forwarded headers/partición de rate limiting tras Ingress siguen como deuda operativa previa, no como protección deshabilitada.
- Una repetición local de Sensor Tests fue bloqueada por Windows App Control (FileLoadException 0x800711C7 en Sensor.Application.dll). No se modificó esa protección. No presentar esos fallos de carga como aserciones de negocio aprobadas; consultar el resultado Linux adicional cuando esté disponible.
- Persisten advertencias NuGet preexistentes sobre System.Security.Cryptography.Pkcs 9.0.11; no se declara una auditoría integral de seguridad ni ausencia de vulnerabilidades. No se probó carga sostenida, restauración de snapshot ni alta disponibilidad de nodo.
